# 产品文档：学习通待办工具

术语见 [CONTEXT.md](../CONTEXT.md)。架构决策见 [docs/adr/](./adr/)。本文只写问题、范围和验收标准，不记录变更历史——那是 git log 的职责。

---

## 问题陈述

用户需要及时看到学习通即将截止的作业和考试。学习通自身的通知分散在收件箱里，容易漏看；课程空间中还存在从未发过通知的作业和考试。

工具面临的核心风险是[静默失效](../CONTEXT.md)：界面一切正常、没有任何报错，但本该出现的待办没有出现，本该响的提醒没有响。用户一旦开始依赖工具就不再自己核对，因此一次静默的漏比一次明显的报错代价高得多。所有设计取舍以此为准：宁可犯可见的错，不可犯静默的漏。

---

## 范围

### 在范围内

- 在本机保存学习通登录凭据，直接访问学习通读取数据，不经过任何自建服务端。
- 从收件箱通知和[受监控课程](../CONTEXT.md)两类[来源](../CONTEXT.md)发现[待办事项](../CONTEXT.md)，按业务 ID 合并，同一件事只呈现一次、只提醒一次。
- 解析截止时间，按截止时间排序并区分已过期、今日截止、未来待办和无截止时间。
- 按[提醒规则](../CONTEXT.md)在截止前发出系统通知，用[提醒去重键](../CONTEXT.md)避免重复。
- Windows：定时刷新、系统通知、托盘常驻、开机自启、单实例、安装程序。
- Android：应用内登录、预排本地闹钟提醒。
- [认证失效](../CONTEXT.md)必须对用户可见。

### 不在范围内

- Cloudflare Worker、CalDAV、Google Calendar、ICS 订阅、远端同步接口。这些是历史架构，文档中不再描述，也不做迁移。
- 两端之间的数据同步或配对。见 CONTEXT.md 中的[平台角色](../CONTEXT.md)：重复提醒是刻意接受的代价。
- App 完全退出后的后台服务、Windows Service、系统计划任务或远端推送。
- 绕过学习通的验证码、二次验证或风控。
- 把凭据、同步数据或提醒历史上传到任何远端服务。

## 验收标准

### 同步与展示

- [x] 凭据保存在设备安全存储中，不进入普通配置、缓存、日志、诊断导出或界面回填。
- [x] 能完成认证检查、收件箱定位与分页、通知筛选、详情链接提取、作业/考试页解析。
- [x] 同步结果包含待办列表、失败列表、认证状态和最近同步时间。
- [x] 待办按截止时间排序，并给出展示状态和距截止小时数。
- [x] 能抓取课程/班级列表、课程作业列表和考试测验列表，解析入口 URL 与截止时间。
- [x] 明确标记为已完成、已提交、已过期或只能查看的事项被过滤；状态不明确的事项保留。
- [x] 同一业务 ID 来自多个来源时合并展示并复用提醒身份，保留来源列表。
- [x] 单条通知、单门课程或单个任务失败只写入诊断，不中断整轮同步。
- [x] 网络失败或认证失败不清空已缓存的待办。
- [x] 已用真实学习通账号完成端到端同步验收。

### 提醒

- [x] 自动刷新定时器按配置周期运行，隐藏到托盘后继续，明确退出后停止。
- [x] 提醒去重历史在每轮处理前清理：保留最近 90 天、最多 1000 条，丢弃异常未来时间。
- [ ] 提醒去重键包含提醒规则维度。当前实现只含待办事项与截止时间快照，缺少规则维度；以 CONTEXT.md 的定义为准，实现待修正。
- [ ] 真实 Windows 通知可显示、点击可打开 App 或目标详情。
- [ ] 托盘可常驻，支持打开窗口、立即同步、暂停/恢复通知、查看登录状态、退出。

### 安全边界

- [x] 所有带凭据的请求走统一 HTTP 客户端，目标限制为显式学习通 HTTPS 主机集合，不接受任意子域。
- [x] 重定向逐跳手动校验，不会带着凭据跟随到集合之外。
- [x] 交给系统浏览器的外链同样只允许该主机集合；缓存中的第三方、HTTP 或畸形 URL 不形成可点击外链，启动失败提示不回显完整 URL。
- [x] 请求主机、Cookie Domain、WebView 顶层导航和详情外链共用同一 URL 策略模块，避免多处 allowlist 漂移。
- [x] 手动凭据输入在解析前做源级 CR/LF 检查，命中即整份拒绝：不认证、不保存、不发送；保存成功后清空输入框。
- [x] 控制器加载历史配置时重新校验凭据；不安全值在内存中隔离为未配置，并通过专用操作单独删除该凭据而不改其他偏好。删除失败不削弱内存隔离。
- [x] 错误摘要、失败列表和诊断导出脱敏凭据、token、账号类 query 和响应正文。
- [x] 系统通知默认使用不含课程名、任务名和截止时间的通用文案；用户可显式开启详情，偏好只保存布尔值。

### 交付

- [x] CI 在 Windows runner 上执行 analyze、test、release build，并验证单实例行为。
- [x] 发布产物包含 Windows 压缩包与 Android APK，附 SHA256SUMS 与安全边界说明。
- [x] 上传前审计产物内容，拒绝 `.dev.vars`、环境文件、测试/fixture 目录和本地运行时数据库；CI 从干净 checkout 构建，不注入真实凭据。
- [x] Android 正式发布使用固定 release keystore 并通过 `apksigner verify`；缺少密钥时正式发布失败，密钥文件不进入版本控制或产物。
- [x] Android 的 namespace、applicationId、Manifest 入口与 Kotlin package 一致性在构建前检查。
- [x] Android Manifest 关闭系统备份与明文网络，不声明 HTTP VIEW query。

## 约束

### 性能

- 单轮同步不并发；已有同步在运行时新触发应跳过或合并。
- 收件箱、详情和课程抓取受条目上限约束，避免频繁访问触发风控。
- 详情类请求最多 6 路并发。真实账号实验表明提高到 8 路会触发明显拥塞并产生失败，总耗时反而大幅恶化，因此固定为 6。
- 已测得的单轮同步基线约 18.6 秒：认证 0.5、通知列表 2.7、通知详情 2.9、任务详情 6.8、课程扫描 5.7。主要瓶颈是请求数量而非单次延迟。
- 启动时 5 分钟内的缓存直接展示，不立即重复全量同步。
- 成功或部分成功后 60 秒内的手动刷新显示剩余等待；配置变更、失败重试和后台定时刷新不受此限。
- 同步失败摘要命中限流信号时进入 5 分钟内存退避；重启时按缓存时间恢复未结束的退避，未来时间戳不参与恢复。
- 每次同步和登录校验使用独立 HTTP 客户端并在完成后关闭；明确退出时关闭全部活跃客户端。
- 每条请求连同完整重定向链共享单一超时预算，不逐跳重复计时。
- 配置在存储读写和控制器加载/应用边界统一规范化：通知页数 1–20、条目数 1–500、课程数 1–100；自动刷新允许 0 表示关闭，否则限制为 15–180 分钟。
- Windows 使用用户会话级命名 Mutex 保证单实例；第二实例通过注册消息请求主实例恢复聚焦，不依赖窗口标题。
- 界面优先展示缓存结果。

### 存储

- 凭据必须进入设备安全存储。普通配置、同步缓存、提醒历史和提醒配置可以进入普通偏好存储。

### 技术栈

- 当前生产实现：Android 为 React Native（`apps/chaoxing_rn`），Windows 为 TypeScript 本机宿主 + C# 外壳（`apps/chaoxing_windows`）。见 [ADR-0002](./adr/0002-react-native-incremental-migration.md)、[ADR-0003](./adr/0003-windows-native-host.md) 与 [rn-production.md](./rn-production.md)。
- Flutter/Dart 参考实现在 `legacy/chaoxing_app`，不再出货，CI 只分析/测试。
- 可移植领域切片（提醒规则、URL 信任分级、同步与解析）用 TypeScript 写在 `packages/chaoxing-domain`。

## 风险

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| 只依赖收件箱导致漏项 | 高 | 中 | 受监控课程作为第二来源补漏，按业务 ID 合并。 |
| 学习通页面结构变化导致解析失败 | 中 | 高 | fixture 覆盖关键页面；局部失败写入诊断而非静默丢弃；脱敏诊断导出辅助定位。 |
| 桌面通知/托盘插件兼容性问题 | 中 | 高 | 先做抽象层和 fake 测试，再做真机验收；失败时给出可见的错误摘要和恢复入口。 |
| 凭据泄漏到第三方域名、日志或诊断文件 | 低 | 高 | 统一客户端 allowlist、逐跳重定向校验、安全存储、错误脱敏、发布产物审计。 |
| 重复提醒轰炸 | 中 | 中 | 系统通知调用成功后才写入去重历史；历史定期清理。 |
| 风控、验证码或登录失效 | 中 | 中 | 不绕过风控；认证失效对用户可见并要求重新登录；降低自动同步频率；保留缓存。 |
| 发布产物包含敏感数据 | 低 | 高 | 上传前内容审计；CI 从干净 checkout 构建，不注入本机 secrets。 |

## 验收测试

### 自动

```sh
cd packages/chaoxing-domain && npm test && npm run typecheck
cd ../chaoxing-android-alarms && npm test && npm run typecheck
cd ../chaoxing-android-http && npm test && npm run typecheck
cd ../../apps/chaoxing_rn && npm test && npm run typecheck
cd ../chaoxing_windows && npm test && npm run typecheck
```

生产 APK / Windows 外壳由 `.github/workflows/chaoxing-rn.yml` 在 GitHub-hosted runner 上构建。Flutter 参考实现不再作为发布验收：

```sh
cd legacy/chaoxing_app
flutter analyze
flutter test
```

单实例脚本在 Release 产物上验证隐藏窗口恢复、第二实例退出，以及目标路径下只保留一个主进程。

### 手动

- 关闭主窗口，进程隐藏到托盘并继续运行。
- 托盘菜单包含打开窗口、立即同步、暂停/恢复通知、查看登录状态、退出。
- 同步中点击立即同步，不会启动第二轮。
- 暂停通知后自动同步继续但不发通知。
- 退出后进程结束，不再同步或通知。
- 构造一件命中提醒规则的待办，系统通知出现一次且去重历史记录对应的键。
- 点击通知，App 打开或聚焦并能定位到对应事项。
- 启用受监控课程后，没有收件箱通知的课程作业和考试也出现在待办中。
- 同一件事来自多个来源时只出现一次，同一条规则最多提醒一次。
- 诊断导出包含失败摘要，但不含凭据、token、账号 ID 或响应正文。
